# 为 better-sidebar 的 Git 视图添加轨道式提交图

## 目标
侧边栏「源代码管理」(dsh-better-sidebar 插件 `GitView`)的历史列表左侧增加 VSCode 风格轨道式提交图:圆点=提交、竖线=分支轨、合并线随父提交转折。点击行看 diff 等现有交互不变。无新第三方依赖。

## 1. 建立本地开发基线(新目录 E:\A_Project\DSH-better-sidebar)
```
git clone https://github.com/omdsh-dev/DSH-better-sidebar
git checkout 5e416eccef277067a4e4b9d655044e8bc45b243c   # 与本机安装副本同源
npm install && npm run build                              # tsc + tsdown
```
对照:构建产物与本机 `~/.dsh/profiles/node_modules/dsh-better-sidebar/lib/*.js` 基本一致,确认工具链没漂移后再动工。

## 2. 服务端:让数据带拓扑
`src/git.ts` 的 `log()`:`--pretty=format:%h%x1f%s%x1f%an%x1f%ai%x1f%H%x1f%D` 追加 `%x1f%P`(父哈希)、`%x1f%ct`;`parseLogLines` 同步解析。`GitLogEntry` 增加 `parents: string[]`(两个类型文件都要改:`src/git.ts` 与 `src/client/api.ts` 镜像)。向后兼容——只是多一个字段。

## 3. 客户端:轨道渲染组件
- 新文件 `src/client/CommitGraphRail.tsx`:输入带 `parents` 的 `GitLogEntry[]`,做车道分配(lane 占用/释放算法,~150 行),每行输出一段内联 SVG 圆点+轨道。
- `GitView.tsx` 历史区(现 359–399 行)每行头部插 rail 单元格;行的菜单/diff 跳转逻辑零改动。
- 分页:`loadMore` 追加后对整个已加载窗口重算车道;跨页处轨道按第一父提交近似延续(已加载窗口外的拓扑不可见——实现时在代码注释里写明这一限制)。
- `sidebar.module.css` `.git` 区(≈1529 行起)新增 `.gitGraph*` 类,只用主题 token(`--dsw-alias-*`),明暗双主题自动适配。
- `locales.ts`:zh/en 两块同步加必要的键(tooltip 等)。

## 4. 构建并换装到 web profile
- 本地仓库 `npm run build`。
- `dsh plugin --profile web add <本地目录>`(CLI 支持路径 spec 并自动 reconcile bundle 配置),将 tarball 安装版替换为本地修改版。
- 回退方式(写入交付说明):`dsh plugin --profile web add dsh-better-sidebar@^0.13.0` 一条命令还原官方版。
- 注记:本地路径安装会脱离 npm semver 自动更新,升级=未来手动合并上游后重新构建换装。

## 5. 验证(全部给出实测证据)
1. 重启 `dsh web`(先停当前后台任务)。
2. `curl` 确认 `/sidebar/api` 与页面资源 200、chunk 服务正常。
3. 浏览器打开 Web UI → 侧边栏 Git 标签:截图确认轨道图渲染在本仓库历史上;点任一提交行,确认 diff 视图照常打开;切换明暗主题各验一次。
4. 若面板异常,以第 4 步的回退命令立即还原并如实报告。

## 不做的事
- 不动 `~/.dsh` 的 cordis.patch.yml 现状(当前 web 能正常启动,不碰重复路由相关配置)。
- 不创建 GitHub fork、不推送任何远程。
- 不改 agent loop 或 harness 主仓库任何代码。
