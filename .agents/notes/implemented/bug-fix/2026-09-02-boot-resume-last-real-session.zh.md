# Agent Note：启动时恢复最近的真实会话，而非持久化的空白壳

Status: implemented

[English](2026-09-02-boot-resume-last-real-session.md) | 中文

## 问题

打开 dsh web 总是落在空白会话的 hero 页，且没有头部装饰，尽管用户最近的真实对话（及其会话头部卡片）明明存在。持久化的选择（`dsh.sessions.current`）变成了一个空白会话：应用忠实恢复了它，而会话列表隐藏空白壳，于是 hero 变成了粘性状态——之后每次启动都恢复同一个空白会话。空白壳最初是通过"新建会话"兜底路径被持久化的（最近工作区 → 复用现有空白会话 → 持久化）；而空 localStorage 的场景（隐身窗口）每次都走这条路径。

## 决策

`ui-workspace` 导航的启动初始选择跳过空白会话：

- 持久化选择解析为空白会话时视为无选择；reconcile 继续走最近工作区路径，而不是把空白当作完成。
- 最近工作区连接后，优先打开其中**最近更新且非空白**的会话，而不是 `connectWorkspace` 返回的空白壳。只有工作区里没有任何真实会话时才回退到空白（新会话）行为。

新建会话入口（`startSession`、`connectWorkspace`）不变——显式的新建会话仍然复用/创建空白壳。

## 已否决的替代方案

- **只修一次持久化值** —— 否决：只要启动回退到新建会话路径（隐身窗口、已归档选择），粘性空白就会复发。
- **不让空白会话进入持久化写入** —— 否决：选择存储理应持久化当前值；"空白壳不是要恢复的对话"这个策略应该写在启动策略里。

## 后果

- 只要最近工作区里有真实会话，启动就会回到上次的真实对话（连同会话头部卡片）。
- 主动关闭在空白会话上的状态不会被记住；启动改为选择最近的真实会话。
