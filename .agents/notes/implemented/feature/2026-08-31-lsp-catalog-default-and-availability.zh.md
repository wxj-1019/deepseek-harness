# Agent Note：LSP 语言目录默认开启并标注可用性

Status: implemented

[English](2026-08-31-lsp-catalog-default-and-availability.md) | 中文

## 问题

`lsp-stdio` 的内置语言目录在文档中写明 `catalog` "默认为 true"，但实现要求显式传入 `config.catalog === true`——省略配置时不会挂载任何种子，与记录的契约相反。每个种子的探测结果（可执行文件解析成功还是缺失）在加载后即被丢弃，也没有任何表面告诉模型 `lsp` 查询实际能服务哪些语言：在装有语言服务器的主机上，模型无从得知 `lsp` 可用；在裸主机上，它只能通过一次次失败的查询来发现。

## 决策

- `catalog` 进入插件 `Config` schema，默认 `true`；省略时挂载内置的 TypeScript 与 Python 种子，与文档化契约一致。可执行文件缺失的种子仍然是跳过而非报错；失败的显式条目仍然响亮失败；catalog 关闭且表为空仍在加载时被拒绝。`mergeServersWithCatalog` 把种子合并提取为纯函数，使默认开启的语义可以在无 I/O 的前提下被钉住。
- 插件保留解析成功的提供方信息，并注册一个有界的 `lsp:language-catalog` system-prompt 提示段，列出每个服务器的 id、扩展名与语言。模型因此只对可服务的文件发起 `lsp` 查询。没有任何提供方解析成功时该提示段不存在。扩展名与服务器数量都有上限，防止过大的服务器表撑大提示；缺失的二进制保留在控制台警告路径上（那是人的关注点，不是模型可见的）。

挂载提示段要求在插件的 `inject` 中加入 `systemPrompt`；直接挂载 `lsp-stdio` 的测试现在同时挂载 `@deepseek-ai/dsh-system-prompt`，而测试显式服务器语义的用例显式传入 `catalog: false`——省略不再等于关闭。

## 已考虑的替代方案

- **保持省略即关闭并修改文档** —— 拒绝：文档化的默认开启契约就是设计本身；裸主机的安全性来自种子跳过，该机制早已存在。
- **在逐查询错误上标注可用性** —— 拒绝：那是让模型在一次失败调用之后逐个扩展名地学习；提示段直接避免了这次失败调用。
- **通过工具输出字段暴露目录** —— 拒绝：模型需要在决定调用之前知道可用性，而不是在某次无关结果内部。

## 后果

- PATH 上装有 `typescript-language-server` 或 `pyright-langserver` 的主机无需显式配置即可获得这些提供方；没有的主机行为与之前相同（无提供方，逐查询响亮失败）。
- 之前省略 `catalog` 并依赖"省略即关闭"的配置必须显式设置 `catalog: false`。
- 提示最多增加几百字节，受提示段上限约束。
