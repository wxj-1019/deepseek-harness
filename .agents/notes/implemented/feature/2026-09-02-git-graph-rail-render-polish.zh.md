# Agent Note：git-graph 轨道渲染——拉伸 viewBox 曲线与图表色系

Status: implemented

[English](2026-09-02-git-graph-rail-render-polish.md) | 中文

## 问题

第一方提交轨道把换轨画成直线对角线，轨道用语义状态色着色（红色轨道读作失败而非分支），圆点无装饰，且图直接贴在透明的 aqua 表面上——壁纸与图谱争夺注意力，哈希几乎不可见。

## 决策

- **未知行高下的曲线渲染。** SVG 保留拉伸行契约，但从百分比 `line` 属性切换到 `0–{laneWidth}×100` 的 `viewBox` 加 `preserveAspectRatio="none"`：y 单位保持百分比等价（行仍在共享边界相接），x 单位保持轨道像素，`non-scaling-stroke` 在非均匀拉伸下把每条描边锁定在屏幕宽度——这正是贝塞尔 S 曲线合并边（控制点在行高的 72/78%）能平滑渲染而不是出现锯齿的原因。
- **配色。** 轨道使用应用的图表系列色（与用量图表同一组）。有意排除语义状态色——红色轨道读作失败；不同的色相承载泳道标识，不给图谱附加语义。轨道降到 75% 不透明度，让圆点领先。
- **ref 徽章分层。** HEAD 指向的引用以强调色填充（一眼认出检出分支），tag 用暖色描边，其余保持浅底胶囊。
- **表面。** 视图落在近乎不透明的圆角面板上，带 aqua 玻璃配方的内嵌顶部高光；哈希移到 label-secondary（原来的 tertiary 在壁纸上消失）。

## 后果

- 行高仍然只驱动拉伸；分配算法不变。
- 圆点的背景环采样 `--dsw-alias-bg-base`，更换面板填充时需同步更新环色。
