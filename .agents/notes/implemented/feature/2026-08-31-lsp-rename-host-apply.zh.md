# Agent Note：rename 可由宿主代为落盘，显式开启

Status: implemented

[English](2026-08-31-lsp-rename-host-apply.md) | 中文

## 问题

`rename` 返回工作区编辑计划，由模型用自己的文件编辑工具应用。对于机械性的多文件重命名，把计划逐条誊写回编辑调用是有损的重复劳动，模型可能出错。

## 决策

`rename` 新增模型可见的 `apply` 标志，默认 `false`。设为 `apply: true` 时，工具自己转换计划：每个 `file:` URI 转为必须落在会话工作区内的绝对路径（非 `file:` scheme 与工作区外路径会在任何写入之前拒绝整次调用），文本编辑折叠进当前内容（按文档末尾优先应用；重叠与越界坐标直接拒绝），每个文件经带版本守卫的替换意图写入。中途写入失败会把已写入文件回滚为应用前内容——恢复不携带信号，与 multi_edit 的回滚契约一致。随后工具报告 `{kind: 'rename-applied', applied, files}`；不带标志时，仅返回计划的原有行为不变。

## 已考虑的替代方案

- **总是代为落盘** —— 拒绝：计划优先的默认值把模型基于 diff 的评审作为主路径。
- **服务器端 `workspace/applyEdit`** —— 拒绝：本机按设计拒绝该请求。
- **在提供方内应用** —— 拒绝：工具拥有模型可见策略且已持有会话工作区；把应用留在工具层使接缝保持宿主中立。

## 后果

- `lsp` 工具在被告知时会写入；`inject` 新增 `fs`，未设 `apply` 时工具仍是只读的。
- 包含关系按会话工作区强制执行，语言服务器无法把写入移出工作区。
- 回滚语义与 multi_edit 一致：失败的应用把工作区恢复原状，恢复失败时点名残留文件。
